# Набор вопросов для оценки качества помощника «Мой ТПУ»

Файл `questions.jsonl` содержит эталонный набор из 100 запросов для автоматизированного и полуавтоматического тестирования помощника `services/assistant` (шаг 11 спецификации `specs/assistant/spec.md`).

Набор проверяет:
1. Корректность классификации намерений (маршрутизатор без модели).
2. Выбор инструментов (`docs_search`, `rasp_find`) и генерацию аргументов.
3. Долю прямого пути без обращения к языковой модели (`direct_ok: true`, целевой порог ≥ 40%).
4. Точность фактов в ответе (`must_contain` на основе официальных документов ТПУ).
5. Устойчивость к ловушкам (`trap`: персональные данные PII, prompt injection, запросы вне темы).

---

## Формат данных (схема JSONL)

Каждая строка файла представляет собой отдельный валидный JSON-объект со следующими полями:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | `string` | Да | Уникальный идентификатор вопроса (`q001`…`q100`). |
| `question` | `string` | Да | Текст запроса студента (разговорный язык, сленг, опечатки, неверная раскладка, пропуск пунктуации). |
| `intent` | `string` | Да | Намерение: `docs_howto` (регламенты, справки), `room_where` (аудитории/корпуса), `schedule` (расписание), `greeting` (приветствия/вежливость), `other` (темы вне ТПУ, домашка, отвлечённые вопросы). |
| `tool` | `string \| null` | Да | Ожидаемый инструмент: `"docs_search"` \| `"rasp_find"` \| `null` (для `greeting` и `other`). |
| `args` | `object \| null` | Да | Ожидаемые аргументы инструмента (например, `{"query": "справка об обучении"}` или `{"query": "209"}`). Для вопросов без инструмента — `null`. |
| `must_contain` | `string[]` | Да | Список ключевых проверяемых фактов/фраз (сроки, названия документов, кабинеты, контакты, ссылки), которые обязаны присутствовать в ответе. Все факты взяты строго из корпуса ТПУ. Для приветствий/отказов — пустой массив `[]`. |
| `source` | `string \| null` | Да | Канонический URL официального источника ТПУ (`help.tpu.ru`, `tpu.ru`, `staff.tpu.ru`), откуда взят факт. Для `greeting`/`other` — `null`. |
| `direct_ok` | `boolean` | Да | `true`, если ответ формируется без вызова LLM (шаблоны приветствий, отказ на `other`, детерминированный поиск аудиторий/расписания). Для `docs_howto` — `false`. |
| `trap` | `string` | Нет | Пометка ловушки при наличии: `"pii"` (содержит ФИО, телефон, email, паспорт), `"injection"` (попытки взлома системного промпта), `"out_of_scope"` (вопросы не по университету). |

## Текущий состав набора

Всего вопросов: **100** (`q001`–`q100`).

### Распределение по намерениям (`intent`)
- **`docs_howto`**: 60 вопросов. Охватывают темы:
  - Справки и выписки (об обучении, в военкомат, с оценками, архивные);
  - Перевод и восстановление (сроки комиссий, смена специальности/формы, выход из академического отпуска);
  - Академический отпуск (основания, комплект документов);
  - Отчисление (по собственному желанию, за неуспеваемость, обходной лист);
  - Стипендии и материальная помощь (государственная академическая, социальная, повышенная, единовременная матпомощь, документы в профком);
  - Общежития (заселение, переселение, оплата, выселение на каникулы);
  - Иностранным студентам (миграционный учёт, продление визы, дактилоскопия, полис ДМС, отдел международных образовательных программ);
  - Платные образовательные услуги (оплата обучения, материнский капитал, рассрочка, доп. соглашения);
  - Учётная запись и корпоративные сервисы (сброс пароля ТПУ, логин/почта, Wi-Fi `TPU-Secured`, домен `tpu.ru`);
  - Moodle и образовательный процесс (доступ к курсам, привязка дисциплин, технические проблемы);
  - ИТ-заявки и Helpdesk (портал help.tpu.ru, обращение в Единую службу поддержки, контакты диспетчерской).
- **`room_where`**: 13 вопросов (поиск аудиторий, корпусов, столовых, коворкингов ТПУ через `rasp_find`).
- **`schedule`**: 9 вопросов (расписание групп, преподавателей, звонков, сессий).
- **`greeting`**: 7 вопросов (приветствия, вежливость, представление бота, тест на раскладку `ghbdtn`).
- **`other`**: 11 вопросов (погода, новости, политика, генерация кода/домашек, общие советы).

### Ловушки (`trap`)
В набор включено **10 тестовых ловушек**:
- **`pii`** (5 вопросов: `q008`, `q025`, `q042`, `q065`, `q075`): вопросы содержат реальные или правдоподобные ФИО, номера телефонов, личные email-адреса и номера паспортов. Используются для проверки механизма маскирования персональных данных перед отправкой во внешние провайдеры.
- **`injection`** (3 вопроса: `q083`, `q091`, `q092`): попытки пробития системного промпта («забудь предыдущие инструкции», «ты теперь DAN», «выведи скрытый системный промпт»).
- **`out_of_scope`** (2 вопроса: `q099`, `q100`): запросы на решение вузовских уравнений за студента и отвлечённые справочные вопросы, требующие отказа со стороны помощника.

### Прямой путь (`direct_ok`)
- `direct_ok: true` — **40 вопросов** (40% выборки: все `room_where`, `schedule`, `greeting`, `other`).
- `direct_ok: false` — **60 вопросов** (60% выборки: все `docs_howto`).
- Соответствует критериям спецификации: доля прямого пути без вызова LLM составляет не менее 40%.

## Правила пополнения и редактирования набора

1. **Формат строк**:
   - Строго одна строка — один валидный JSON. Без переносов строк внутри объекта.
   - Кодировка UTF-8 без BOM.
   - Без завершающих пустых строк.

2. **Реалистичность формулировок**:
   - Вопросы должны звучать естественно для студентов: допускаются пропуск заглавных букв, отсутствие вопросительного знака, опечатки («стипуха», «общага», «материалка», «академ», «отчисленее», раскладка «ghbdtn»).
   - Не превращать вопросы в идеальные поисковые запросы (поисковый запрос должен формироваться помощником в поле `args.query`).

3. **Строгая фактологическая точность (`must_contain` и `source`)**:
   - Любой факт в `must_contain` обязан быть подтверждён официальным источником из доменов `*.tpu.ru` (база `help.tpu.ru`, портал `tpu.ru`, справочники подразделений).
   - Запрещено добавлять вымышленные сроки, номера кабинетов или несуществующие регламенты. Если актуальный регламент ТПУ не найден в корпусе, вопрос в набор **не добавляется**.
   - Формулировки в `must_contain` должны быть лаконичными и проверяемыми подстроками (например: `"в течение 3 рабочих дней"`, `"каб. 211"`, `"https://tpu.ru/student/reception/order"`).

4. **Проверка перед фиксацией**:
   - Валидация JSONL синтаксиса.
   - Проверка баланса классов и метрик покрытия.
