# Как добавить API в шлюз

Новое API — пакет `services/gateway/src/main/java/org/mytpu/gateway/integrations/<id>/`: бин `Integration` и инструменты `Tool`
(образец — `integrations/example`). Ядро шлюза не трогается. Подключение без кода (коннекторы) — спецификация 2.

## Ответ инструмента
- `summary` — готовая фраза на русском; `data` — запись (record) для карточки; `hint` — что делать дальше (`docs/LLM.md`, раздел 2).
- Описание, подсказки к аргументам и `title` — в `src/main/resources/tools/descriptions.properties`, не в коде.

## Личные данные (specs/personal-data-for-agents)
Если инструмент отдаёт личное (`ToolDescriptor...sensitivity(Sensitivity.PERSONAL)` или `SENSITIVE`):
1. **Каждое поле ответа** — с пометкой `@Classified(value = …, mask = …)`, включая вложенные записи и элементы списков.
   Без пометки шлюз не стартует и назовёт инструмент и поле.
   - `PUBLIC` — можно всем (название школы, номер аудитории);
   - `PERSONAL` + маска: `HIDE` (убрать), `INITIALS` (ФИО → «И. И. И.»), `COUNT` (список → сколько), `COARSE` (дата → месяц);
   - `SENSITIVE` — оценки, заявления, почта, медицинское: внешний агент их не получает никогда.
2. **Безопасная фраза**: `ToolAnswer.personal(summary, publicSummary, data)`. `publicSummary` — та же мысль без ПД
   («3 дедлайна, ближайший — через 2 дня»). Без неё внешний агент получит общую фразу «Ответ показан в «Мой ТПУ»».
3. **Варианты выбора** (`needs_choice`) — без ПД: группа, курс, номер заявки, а не ФИО. Шлюз их не маскирует.
4. Списки длиннее `maxItems` (по умолчанию 20) шлюз обрежет сам и допишет «показано N из M».
5. Вызов личного инструмента без пользователя (мастер-ключ без входа ТПУ) шлюз не допустит; проверить режимы на dev-стенде —
   заголовки `X-Dev-*` (`services/gateway/README.md`).
