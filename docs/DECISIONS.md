# Решения

Формат: дата — решение — почему — отвергнутая альтернатива. Подробности — документы в `helpdesk-ai/docs/handoff`.

- 2026-10-02 — продукт = MCP-шлюз, сайт и мобилка — демо-клиенты — ценность в едином входе к сервисам ТПУ для агентов — «приложение со встроенным чатом» как продукт
- 2026-10-04 — своим клиентам серверная сессия (cookie / `X-Auth-Token`), JWT только внешним — сессию можно отозвать мгновенно; JWT для MCP требует стандарт — JWT для всех
- 2026-10-04 — запись через черновик + подтверждение человеком на сайте — агент не может сам отправить заявку — подтверждение внутри агента
- 2026-10-06 — цель — 4 сервиса на 4 ГБ (документ 22), монолит `app-all` — запасной для 2 ГБ — границы и так были модулями — 8–10 мелких сервисов (не помещаются в память)
- 2026-10-06 — без Spring Cloud, Kafka, Keycloak, Redis: caddy, outbox в Postgres, свой модуль входа — минус 2–4 ГБ инфраструктуры — стандартный набор Spring Cloud
- 2026-10-06 — JdbcClient + Flyway, без JPA — меньше Metaspace и быстрее старт — Spring Data JPA
- 2026-10-19 — сразу весь этап 0: корень на Boot 4.1 / Java 25, `ai-backend` → `services/assistant` с починкой — новое не строим поверх старого Boot 3.3 — временный `boot4-parent` рядом со старым кодом
- 2026-10-19 — паспорт вызова (JWT identity на 60 с) вместо голого `X-User-Id` + общего ключа — взломанный сервис не действует от имени произвольного пользователя — заголовки `X-User-*` + `X-Internal-Key` (документ 22)
- 2026-10-19 — токены ТПУ продлеваются только по требованию, без фоновой задачи — доступ к данным студента не живёт вечно без его участия — фоновое продление «чтобы не протухало»
- 2026-10-19 — сроки: сайт 30 мин простоя, мобилка 7 дней, JWT агента 30 мин — баланс удобства и вреда от кражи; настраивается — сроки документа 20 (агент 1 ч)
- 2026-10-19 — MCP без анонима: только мастер-ключи доверенных клиентов; ключ хранит набор разрешённых API — MCP пока для доверенных людей; «один ключ» из документа 20 без identity — анонимный доступ к публичным инструментам
- 2026-10-19 — новые API: кодом (пакет с `Integration`) или коннектором из консоли (только `GET`, SSRF-защита) — простые API без программиста, сложные — без ограничений — только код / только конфиг
- 2026-10-19 — консоли MCP и rag без новых JVM: API в gateway и rag, интерфейс — статика; rag доступен консоли только через gateway — машина 4 / 4 и rag во внутренней сети — отдельный сервис консоли
- 2026-10-19 — инструменты под слабую модель: человеческие аргументы, `summary`/`hint`, `needs_choice`, имена с `_` (`docs/LLM.md`) — GigaChat путает цепочки вызовов и даты — инструменты как обёртки API
- 2026-10-19 — модель векторов multilingual-e5-small int8, `model_version` в схеме — фаворит документа 19, смена без смены схемы — сравнение с rubert-tiny2 сейчас
- 2026-10-19 — ml-server: Native Image только готовим, собираем на сервере — сборке нужно 6–8 ГБ, у ПК столько нет — сборка на ПК или в GitHub Actions
- 2026-10-19 — модель векторов — e5-small с урезанным до ru+en словарём (60 302 токена из 250 037; веса те же, векторы совпадают, `tools/rag/trim_e5_vocab.py`), `model_version` = `e5-small-en-ru-int8-v1` — полный словарь XLM-R давал ~680 МБ памяти rag уже на старте, урезанный — ~290 МБ — полная модель с лимитом rag выше 380 МБ
- 2026-10-19 — rag: куча JVM `MaxRAMPercentage=30` (вместо 55 у остальных), ONNX без пула памяти и предупаковки, пакеты по 4 текста; загрузка корпуса (`rag-ingest`) — отдельный контейнер с лимитом 512 МБ — модель векторов живёт вне кучи; пик загрузки упирается в 380 МБ — общий лимит 380 МБ для поиска и загрузки
- 2026-10-19 — «нашлось» в rag: сходство ≥ 0,87 или ≥ 0,85 при отрыве лучшего куска от десятого ≥ 0,025; на 46 вопросах hit@3 86,5 %, hit@5 89,2 %, ложных «нашёл» 0 из 9 — у e5 сходства сжаты (0,79–0,93), один порог не разделяет вопросы с ответом и без; пороги — в `mytpu.rag.search.*`, пересмотреть при росте набора — один порог 0,86 (11 % ложных «нашёл»)
- 2026-10-19 — door-mcp — свой обработчик MCP Streamable HTTP без состояния (JSON-RPC по `POST /mcp`: initialize, ping, tools/list, tools/call), а не MCP-сервер Spring AI 2 — у сервера Spring AI один список инструментов на всех, а нужен `tools/list` по scopes мастер-ключа и добавление инструментов на ходу (коннекторы); плюс меньше зависимостей и памяти — `spring-ai-starter-mcp-server-webmvc` (stateless)
- 2026-10-19 — `rasp_day` / `rasp_week` отложены до Открытого API расписания или письменного разрешения ТПУ; пока только `rasp_find` со ссылкой на страницу объекта на rasp.tpu.ru — названия дисциплин на сайте скрыты (расшифровка скриптом с ключом от сервера — защита от автоматического сбора), обходить её без разрешения не будем — расшифровка, как в браузере; выгрузка iCal (форма с подтверждением «Ознакомлен»)
- 2026-10-19 — ml-server: движок Ktor CIO вместо Netty; Native Image собирается в `ghcr.io/graalvm/native-image-community:24.0.2`, метаданные — агентом трассировки GraalVM 24 на JVM — CIO проще для Native Image; формат `reachability-metadata.json` требует GraalVM ≥ 23, а Gradle 9.0 запускается на JDK ≤ 24 — образ GraalVM 25 из спецификации (не запустит Gradle 9.0), ручные reflect-config
- 2026-10-19 — gateway: куча `MaxRAMPercentage=40`; всем Spring-сервисам `MinHeapFreeRatio=10`, `MaxHeapFreeRatio=30` — при 55 % Serial GC раздувал кучу gateway до 210 МиБ и не отдавал её: 345 МиБ в простое; стало 146 МиБ в простое и 307 МиБ под нагрузкой — оставить 55 % и поднять лимит gateway
- 2026-10-19 — после ревью: фильтры ключей «закрыто всё» по декодированному пути (обход через `%69`/`;x` закрыт), rag сам ограничивает уровни доступа и не стартует с пустым ключом, тело `/mcp` ≤ 64 КБ, лимит неудачных попыток по IP и общий лимит клиента до проверок, actions в CI закреплены по SHA и деплой только из `main`, ml-server на Ktor 3.5.2, shell-скрипты и Dockerfile — LF через `.gitattributes` — замечания arch-reviewer и security-reviewer — оставить как было до консоли
