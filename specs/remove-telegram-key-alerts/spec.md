# Удаление Telegram из оповещений шлюза

## Зачем

Убрать отправку служебных событий ключей в Telegram из `KeyAlerts`.

## Критерии готовности

- [x] Шлюз не отправляет события на Telegram Bot API, даже если в прежней конфигурации указан его адрес.
- [x] Поле `chat_id` и настройка `chat-id` удалены. Вебхук получает прежний JSON с полем `text`. Правило HTTPS проверено отдельно от локальной доставки.
- [x] При отключённом вебхуке команда приостановки группы и запись `key_events` доходят до слоя доступа к БД.

## Не входит

- Изменение входа пользователей, формата событий в БД и правил приостановки ключей.
- Изменения у внешних получателей вебхуков и в репозитории Where to go.

## Ограничения

- Настроенные адреса Telegram Bot API перестают использоваться. Обычные получатели могут продолжить принимать JSON с полем `text`.
- Значение адреса и секреты не выводятся в журналы. Конфигурация стенда проверяется без чтения и копирования секрета.

## Пре-мортем

- Удаления `chat_id` недостаточно. `KeyAlerts` читает адрес из `key_alert_webhook`; старый адрес Telegram должен отключать доставку ещё при запуске.
- Сбой внешней доставки и повтор одного события проверяются отдельно от записи `key_events` и приостановки группы. Актуальную конфигурацию стенда локальная сборка не проверяет.
