# Ш1 — проверки защитных границ шлюза

Статус: выполнена локально, 20.11.2026. Основа: `specs/security-hardening/research.md`, мера Ш1;
`docs/SECURITY.md`, разделы 14–15. База: `main` `fdac0a5` с локальными изменениями Ш2.
Черновики тестов и правки SSRF находятся в рабочем дереве `claude/gateway-security-tests-d2d907`.

## Зачем
Зафиксировать проверками границы доверия шлюза и завершить начатые тесты после переноса Ш2.
Не переносить черновики вслепую: часть ожиданий в них взята из реализации, а не из требований.

## Критерии готовности
- [x] `ClientAddress`: заголовок от недоверенного соединения игнорируется; от доверенного прокси берётся
  правый недоверенный адрес. Проверены несколько строк заголовка, IPv4/IPv6, отсутствие и некорректный
  адрес в разбираемой части цепочки. Неизвестный адрес не превращается в доверенного клиента.
- [x] `PathRoles`: viewer читает консоль, но не изменяет; обычный ключ не входит в консоль;
  `chat.service` не входит в MCP и консоль; обычный ключ не входит в канал чата.
  Для HEAD у viewer явно зафиксировать чтение без изменения состояния в документации и тесте.
  Не закреплять разрешение ключам консоли пользоваться MCP: это отдельная Ш3.
- [x] `McpKeyFilter`: корректный ключ проходит и передаёт контекст; неверный, истёкший, приостановленный,
  ключ вне разрешённой сети и ключ-ловушка не передаются обработчику. Проверены побочные эффекты
  ловушки и геополитики, ранний отказ без поиска БД для некорректного формата и просроченного v1.
  Неизвестная страна и ошибки поиска ключа проверяются по существующему контракту, не по предположению.
- [x] Существующие `AdminNetworkFilterTest` и `ConsolePortTest` из Ш2 остаются зелёными;
  старую версию фильтра или тестов из Ш1 не переносить.
- [x] `SsrfGuard`: таблицы адресов и URL покрывают публичные и запрещённые сети, IPv4 внутри IPv6,
  пользовательские denied-networks, допустимые и недопустимые схемы/порты/имена.
- [x] Классификатор NAT64 распознаёт только стандартный префикс /96; локальный префикс не интерпретируется
  как вложенный IPv4 и запрещён. Проверка выполняется на исправленном классификаторе без сетевых запросов.
- [x] Ожидания, взятые только из текущей реализации, удалены либо обоснованы явным требованием
  в этой спецификации. Проверки не требуют внешних DNS/HTTP, настоящих ключей или БД.
- [x] Полная `bash .claude/verify.sh`, `git diff --check`, независимые архитектурное и security-ревью успешны.

## Не входит
- Ш3, mTLS, identity/OAuth, изменение схемы БД, консольных экранов и интерфейса инструментов.
- Выкладка и push. Локальные правки Ш2 и CSS сохраняются.
- Полноценное сетевое доказательство защиты от DNS rebinding и нагрузочный тест стенда.
  Таблица IP-адресов сама по себе такого доказательства не даёт.

## Ограничения
- Источники ожиданий: эта спецификация и `docs/SECURITY.md`; черновой тест не является контрактом.
- Производственная правка только в `SsrfGuard.embeddedIpv4`: распознавание стандартного NAT64-префикса
  ограничивается /96, чтобы не обходить существующий запрет локального NAT64.
- HTTP-эндпоинты, DTO и БД не меняются. Совместимость: ранее ошибочно допустимые локальные NAT64-адреса
  будут отклоняться; допустимый стандартный /96 с публичным IPv4 сохраняется.
- Не читать секреты, не менять зависимости. Тесты детерминированы и не ходят во внешнюю сеть.
- Если тест выявит другой дефект, сначала описать источник и расширение плана, затем согласовать правку.

## Пре-мортем
- Проверено чтением `SsrfGuard.allowed` и диффа старого рабочего дерева: в текущем main распознавание
  вложенного IPv4 по первым четырём байтам выполняется раньше запрета `64:ff9b:1::/48`.
  Порядок ветвей проверен статически; уязвимое поведение не воспроизводилось.
- Проявление: локальный NAT64 может считаться разрешённым; первое неверное состояние возникает
  при классификации адреса в `embeddedIpv4`, а не в HTTP-клиенте.
- Частичные сбои: ошибку/перегрузку поиска ключей нельзя превращать в допуск; существующие проверки
  `KeyLookupBusyTest` сохраняются. Моки не доказывают транзакционность событий при отказе БД.
- Одновременность: одноразовые эффекты ловушек и геополитики в БД не доказываются юнит-тестом фильтра;
  нагрузка и межзапросные гонки остаются отдельной проверкой. Текущие concurrency-тесты не ослабляются.
- `verify.sh` не подтверждает фактическую маршрутизацию Docker/SSH, реальную доступность внешних API
  и поведение DNS при сетевой атаке; результаты локальных проверок не выдавать за проверку стенда.
