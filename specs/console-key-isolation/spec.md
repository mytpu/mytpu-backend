# Ш3 — изоляция ключей консоли от MCP

Статус: выполнена локально, 20.11.2026. Основа: мера Ш3 в исследовании безопасности и разделы 14–15 `docs/SECURITY.md`.

## Зачем

Ключи `console.admin` и `console.viewer` нужны для управления шлюзом. Сейчас `PathRoles.checkAccess` допускает их
к MCP, где доступ к инструментам зависит от scopes. Роль консоли должна ограничивать канал даже при наличии MCP scopes.

## Критерии готовности

- [x] После прохождения проверок порта, Origin, срока и сети запрос с любой ролью консоли получает HTTP 403 и код `insufficient_scope` на `/mcp` и `/mcp/**`
  независимо от метода и scopes. Это относится и к `POST /mcp/key/rotate`.
- [x] Ключ без ролей консоли и `chat.service` проходит проверку канала MCP. Доступ к отдельным инструментам
  по scopes по-прежнему определяет исполнитель.
- [x] На административном порту `console.viewer` сохраняет чтение через GET и HEAD. Запись доступна
  `console.admin`. Существующий административный API `/internal/**` остаётся доступен по тем же правилам.
- [x] `chat.service` без ролей консоли сохраняет доступ к `/chat/**`. Если роли консоли и `chat.service`
  совмещены в одном ключе, доступ к MCP, консоли и чату отклоняется из-за конфликта ролей.
- [x] Тесты `PathRolesTest` покрывают матрицу ролей. Тесты `McpKeyFilterTest` подтверждают HTTP 403,
  код ошибки и завершение запроса до вызова обработчика. Проверки порта Ш2 и полная `bash .claude/verify.sh` проходят.

## Не входит

Изменения выпуска ключей, миграции БД, изменения интерфейса консоли, mTLS и выкладка на стенд.

## Ограничения

- Решение в `PathRoles`, с существующим сообщением `access.mcp_role` для MCP и существующим форматом ошибки.
  Проверки срока ключа, сети и порта остаются на прежних местах.
- Ключи двойного назначения «консоль + MCP» потребуют отдельного MCP-ключа. Перевыпуск ключей консоли
  администратором сохраняется через `POST /admin/api/keys/{id}/reissue`.
- Клиентские сценарии консоли и скрипты стенда проверены статически. Для работы им нужен административный API,
  обращений к MCP-самоперевыпуску из них не найдено. Содержимое и использование выданных на стенде ключей не проверялось.

## Пре-мортем

- `KeyRules` допускает несколько ролей и scopes. Проверка только в `tools/call` оставила бы другие MCP-маршруты;
  ограничение ставится на входе и покрывает корень и дочерние пути.
- Отказ на защищённом канале проверяется до обработчика. Сбой поиска ключа и лимит поиска продолжают покрываться
  тестами Ш1. Решение о роли не создаёт нового состояния, поэтому параллельные запросы не требуют координации.
- `verify.sh` не подтверждает назначение существующих ключей и доступ через SSH на стенде. Перед выкладкой
  нужно проверить роли используемых ключей без чтения их значений и пройти сценарии администратора и наблюдателя.
