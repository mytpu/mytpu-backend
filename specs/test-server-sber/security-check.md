# Проверка безопасности тестового стенда (31.10–01.11.2026)

Что проверяли: стенд на сервере Сбера снаружи (порты, пути через Caddy, подмена адреса, ключи), код шлюза и
выкладки (субагент `security-reviewer`), секреты в git. Итог: критичных дыр нет; найденное исправлено, кроме
пунктов в «Что ещё усилить».

## Исправлено
1. Чат: `assistant_client_key` в оверлее, `up.sh` создаёт непустой ключ (пустой выключал бы проверку).
2. `StrictPathFilter` в шлюзе (первым в цепочке): 400 на `;`, сегменты `.`/`..`, `%2e %2f %5c %3b %25`, `\`, `//`.
   В Caddy — то же правилом `@suspicious`, сопоставление `/mcp` строго `path /mcp /mcp/*`.
3. Чат получает `TRUSTED_PROXIES`: раньше все клиенты делили один лимит «20 в минуту на адрес» (адрес прокси).
4. `V1_KEYS_UNTIL` на стенде: ключи без контрольной суммы не принимаются — случайные строки не доходят до БД.
5. Ключ клиента чата вычищается из журнала Caddy; `issue-key.sh` создаёт файлы с ключами только для владельца.
6. rag: загрузка корпуса падала (контроллеры поднимались без веб-сервера) — контроллеры только в веб-режиме.
