# Консоль MCP-сервера, консоль rag и подключение новых API без кода

Идёт после `specs/gateway-public-mcp` и опирается на него: контракт `Integration`, каталог, мастер-ключи, журнал, rag с `/internal/search`.
Безопасность — `docs/SECURITY.md` (разделы 3, 5, 14, 15).

## Зачем
Администратор управляет шлюзом и базой знаний без SQL и без программиста: выдаёт мастер-ключи с нужным набором API,
включает и выключает интеграции, смотрит журнал и нагрузку, загружает документы в rag и видит, на какие вопросы база не отвечает.
Простое REST-API (без сложной логики) подключается из консоли за несколько минут; сложное — модулем по инструкции `docs/ADDING_API.md`.
Для показа вузу это видимая часть продукта: «один ключ — нужные сервисы ТПУ», всё под контролем и в журнале.

## Принципы
- **Мастер-ключ.** Ключ клиента — единственное, что клиент знает. В ключе включён набор разрешённых API (scopes = интеграции), выключенные инструменты, лимиты, режим «только чтение», срок. Настоящие ключи ТПУ и сторонних API — только в шлюзе.
- **Два способа добавить API.** (1) Код: новый пакет `integrations.<id>`, реализующий `Integration` — для API с подписью, OAuth пользователя, разбором HTML, логикой. (2) Коннектор из консоли: описание запросов, параметров и ответа — для простого REST/JSON. Оба попадают в один каталог и одинаково проходят исполнитель: проверки, кэш, лимиты, журнал.
- **Без новых JVM.** API консоли — внутри gateway и rag; интерфейс — статические файлы (их раздаёт caddy). Память машины 4 / 4 не растёт.
- **rag остаётся во внутренней сети.** Консоль ходит в rag только через gateway (`/admin/api/rag/**` → rag `/admin/**`).
- **Всё, что меняет администратор, — в журнале действий** (кто, когда, что было, что стало; секреты вырезаны).

## Критерии готовности (проверяемые)

**Доступ к консоли**
- [ ] `/admin/api/**` без ключа администратора или с обычным мастер-ключом → 401/403; ключи консоли имеют роль `console.admin` (всё) или `console.viewer` (только чтение) и выдаются тем же `issue-key`.
- [ ] `/admin/api/**` отвечает только с адресов из `mytpu.admin.allowed-networks` (остальным — 404, чтобы не светить консоль).
- [ ] Интерфейс держит ключ только в памяти вкладки (не в `localStorage`/cookie); 30 минут без действий → выход.
- [ ] Каждое изменение (ключи, интеграции, инструменты, режим, коннекторы, документы rag) — строка в `gateway.admin_audit`: кто (ключ администратора), когда, объект, было → стало; значения секретов — `***`.

**Консоль MCP-сервера**
- [ ] Обзор: состояние gateway и каждой интеграции (включена, здорова, настроена), вызовы и ошибки за 24 ч, p95 по инструментам, топ клиентов — на данных `gateway.audit`, запрос обзора ≤ 300 мс при 1 млн строк журнала (индексы, агрегаты по минутам).
- [ ] Мастер-ключи: список (владелец, префикс, разрешённые API, срок, последний вызов, число вызовов); создание мастером — выбор API галочками из каталога с описаниями на русском, выключение отдельных инструментов, лимиты, «только чтение», срок → ключ показан **один раз** с кнопкой «скопировать» и готовой командой `claude mcp add …`; изменение разрешений действует за ≤ 30 с; перевыпуск (старый ключ живёт ещё N часов, по умолчанию 24); отзыв.
- [ ] Интеграции и инструменты: дерево каталога; включить/выключить интеграцию или инструмент; переопределить TTL кэша, таймаут, лимит (таблица `tool_settings`); видно, каких секретов не хватает (без значений).
- [ ] Режим шлюза: `normal` / `read_only` / `internal_only` с причиной; действует за ≤ 30 с.
- [ ] Журнал вызовов: фильтры по времени, клиенту, инструменту, итогу; аргументов нет (только хэш); выгрузка CSV.
- [ ] Журнал действий администратора с фильтрами.

**Подключение API без кода (коннекторы)**
- [ ] Мастер «Подключить API»: базовый адрес (только `https`), способ входа (`none` / ключ в заголовке / ключ в query / Basic / OAuth2 client_credentials), секрет (сохраняется зашифрованным, обратно не показывается).
- [ ] Инструмент коннектора: имя (`[a-z0-9_]`), описание с примером, `GET`-путь с параметрами `{name}`, параметры (тип, обязательный, умолчание, описание, перечисление), что взять из ответа (JSON Pointer на список или объект, поля и подписи, не больше N элементов), шаблон `summary` (`{field}`), TTL кэша, таймаут, лимит, scope (новый или существующий).
- [ ] Кнопка «Проверить» выполняет вызов из gateway с тестовыми аргументами и показывает сырой ответ (обрезанный до 20 КБ) и итоговый `summary`/`data` — до публикации.
- [ ] «Опубликовать» → за ≤ 30 с инструмент виден в `tools/list` ключам с этим scope (scope нужно явно добавить ключу); у коннектора версии, опубликованная версия не меняется, откат на прошлую — одной кнопкой.
- [ ] Защита от SSRF: адреса, которые резолвятся в частные, loopback, link-local, адреса Docker-сетей и метаданные облака, отвергаются и при сохранении, и при каждом вызове; редиректы на другой хост не выполняются; ответ ≤ 1 МБ, только `application/json`; таймаут ≤ 10 с.
- [ ] Коннекторы — только чтение (`GET`); запись через коннектор недоступна.
- [ ] Пример: публичное JSON-API (например, курсы валют ЦБ или открытое API календаря) подключено через консоль, опубликовано и отвечает в Claude Code — без изменения кода.

**Консоль rag**
- [ ] Обзор: число источников, документов, кусков; модель векторов (`model_version`); дата последней загрузки; последний замер hit@5; размер индекса.
- [ ] Источники: список; добавить файл (PDF, DOCX, HTML, MD, TXT, ≤ 20 МБ) или страницу `*.tpu.ru` по адресу; переиндексировать; задачи загрузки со статусом и коротким логом.
- [ ] Перед индексацией текст проходит `Redactor` (ФИО, телефоны, почта, номера документов → метки, правила из хакатона); в консоли видно, сколько замен сделано.
- [ ] Документы: поиск и фильтр; просмотр разделов и кусков; уровень доступа (`public` / `students` / `staff`); выключить или удалить (уходит из поиска сразу).
- [ ] Песочница: запрос → куски с оценкой по векторам, по тексту, итоговым местом RRF и причиной «не нашлось» (ниже порога).
- [ ] Замер: запуск набора вопросов → hit@3 / hit@5 / ложные «нашёл»; история прогонов; редактирование вопросов и ожидаемых документов.
- [ ] Ненайденные запросы: запросы с `found=false`, сгруппированные по смыслу, с числом повторов — список «чего не хватает в базе»; тексты запросов хранятся уже после `Redactor`, 30 дней.
- [ ] Одиночная загрузка из консоли идёт в фоне внутри rag (одна задача за раз, ONNX на 2 потоках), полная переиндексация — ночным процессом `rag-ingest`; во время загрузки поиск отвечает, RSS rag не выходит за 380 МБ.

**Документы и архитектура**
- [ ] `docs/ADDING_API.md`: как добавить API кодом (пакет, `Integration`, секреты, описания, проверка) и коннектором (по шагам консоли), когда какой способ выбрать.
- [ ] Ни один файл не превышает лимиты; классов `*Manager` нет; контроллеры консоли — по одному на раздел, ≤ 200 строк.

## Не входит (non-goals)
- Вход в консоль через ТПУ и роль `admin` из identity — когда будет identity (тогда ключи консоли отключаются).
- Коннекторы с записью (`POST`/`PUT`/`DELETE`), с токеном пользователя ТПУ, с разбором HTML, цепочки запросов — это способ «кодом».
- Заявки внешних приложений на доступ (самостоятельная регистрация) — консоль выдаёт ключи только сама.
- Обход сайта ТПУ целиком и источники Naumen / BookStack в консоли rag — после стартового корпуса.
- Мобильная версия консоли (достаточно ширины от 1024 px).
- Автотесты — тестировщик команды.

## Ограничения
- **Безопасность.** Секреты коннекторов — таблица `gateway.connector_secrets`, AES-256-GCM, мастер-ключ сейфа — файл-секрет, AAD = id коннектора + имя секрета; в журналах, логах и ответах API — никогда. Загружаемые файлы парсятся с лимитами размера, страниц и времени. Ключи консоли — отдельная роль, не совпадают с мастер-ключами клиентов.
- **Архитектура.** gateway: пакеты `admin` (контроллеры консоли), `connectors` (движок коннекторов — это ещё одна `Integration`, ядро не меняется), `stats`; rag-app: пакет `admin`; интерфейс — `console/` (Vite + React + TypeScript). Каталог и реестр инструментов в gateway поддерживают добавление и удаление инструментов на ходу (заложено в `specs/gateway-public-mcp`).
- **Память.** Нет новых процессов. Агрегаты журнала — таблица `audit_minute` (одна строка на минуту × инструмент × клиент), обновляется вставкой при записи журнала; обзор читает её, а не сырой журнал. Загрузка файлов — потоком на том `rag-files`, не в память целиком.
- **Контент.** Тексты интерфейса — файл `console/src/i18n/ru.json`; цвета, шрифты, отступы — токены дизайн-системы сайта (`console/src/theme/tokens.css`, из холста «четыре темы»), не литералы в компонентах.

## Как устроено (для ревью плана)
- gateway `admin`: `AdminKeyFilter` (роль, сеть), `AdminAuditLog`, контроллеры `KeysAdminController`, `CatalogAdminController`, `ModeAdminController`, `AuditAdminController`, `StatsAdminController`, `ConnectorsAdminController`, `RagAdminProxy` (`/admin/api/rag/**` → rag `/admin/**` с сервисным ключом gateway → rag-admin).
- gateway `connectors`: таблицы `connectors`, `connector_versions` (описание в jsonb, статус draft/published/archived), `connector_secrets`; `ConnectorIntegration` (реализует `Integration`, публикует опубликованные версии как инструменты), `DeclarativeTool`, `ConnectorHttpClient` (`SsrfGuard`: резолв и проверка адреса при каждом вызове, запрет редиректов на другой хост, лимиты), `ResponseMapper` (JSON Pointer), `SummaryTemplate`, `ConnectorValidator` (схема параметров, шаблоны, имена).
- gateway `stats`: `AuditMinuteWriter`, `StatsQueries`.
- rag-app `admin` (Kotlin): `SourcesController`, `FilesUpload` (поток на том), `IngestJobs` (таблица `ingest_jobs` + один фоновый исполнитель), `DocumentsController`, `PlaygroundController` (поиск с отладкой оценок), `EvalController`, `MissesController` (ненайденные запросы); `Redactor` (порт правил хакатона) в rag-search.
- `console/`: Vite + React + TS, роутинг `/console/mcp/*`, `/console/rag/*`; `api/` (клиент к `/admin/api`, ключ в памяти), `theme/tokens.css`, `i18n/ru.json`; страницы по разделам критериев.

## Открытые вопросы
1. **Где живёт интерфейс консоли:** в `mytpu-backend/console` (рядом с API консоли, один PR на изменение API и экрана) или в репозитории `frontend` у клиентской команды?
2. **Откуда пускать в консоль до identity:** только из сети ТПУ, только через VPN / SSH-туннель, или с любого адреса по ключу администратора?
3. **Коннекторы только на чтение (`GET`)** на первое время — ок?
4. **Кто загружает документы в rag:** только администраторы, или нужна роль «редактор базы знаний» (загружает, но не трогает ключи и интеграции)?
5. **Уровни доступа документов** (`public` / `students` / `staff`) нужны уже сейчас, или пока всё публичное?
6. **Тема интерфейса:** светлая и тёмная из холста «четыре темы» (как у сайта) — или консоль в одной теме?
