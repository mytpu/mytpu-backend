# Помощник «Мой ТПУ»: ответы по данным ТПУ, а не «как нейросеть» (спецификация 5)

Сейчас `services/assistant` — тонкая прослойка: сообщение уходит в ml-server как есть, без системной подсказки,
истории и инструментов. На стенде Сбера (01.11) на «Как получить справку об обучении?» он переспрашивает, где вы
учитесь, хотя ответ лежит в базе документов. Эта спецификация делает помощника таким, как задумано в `docs/LLM.md`:
код понимает и проверяет, модель только пересказывает.

## Зачем
- Студент получает ответ с источником из документов ТПУ и расписания, а не выдумку модели.
- Простые вопросы («где ауд. 101 10-го корпуса», «справка об обучении») отвечаются без модели — быстро и бесплатно.
- Ни один факт (время, дата, аудитория, ссылка) не попадает в ответ, если его нет в данных инструмента.
- Личные данные не уходят во внешнюю модель без маски — требование 152-ФЗ и решения директора (01.10).

## Часть А — до входа через ТПУ (только открытые инструменты)
### Критерии готовности
**Путь вопроса**
- [ ] Нормализация в коде: раскладка (`ghbdtn` → «привет»), группа `8к31` → `8К31`, аудитории, даты по-русски
  («завтра», «в пятницу», «12 ноября») → точная дата по Томску. Табличные юнит-тесты.
- [ ] Маршрутизатор без модели (правила): намерения «где аудитория», «расписание группы/преподавателя»,
  «документы: как сделать», «приветствие», «другое». Уверенное намерение со всеми слотами → прямой путь.
- [ ] Слоты хранит сервер (не модель): группа, дата, преподаватель; «а завтра?» берёт группу из прошлого вопроса.
  История — в БД `assistant` по `conversation_id` (Flyway), последние 6 сообщений, только после маскирования личного;
  срок хранения — по ответу на вопрос 4 (предложение: 30 дней, задача очистки).
  `meta` отдаёт настоящий `conversation_id`.
- [ ] Прямой путь: инструмент → карточка с `summary` и ссылкой, ml-server не вызывается (проверка — счётчик вызовов).
- [ ] Путь с моделью: 3–5 инструментов от маршрутизатора, подсказка из ресурсов (по-русски, ≤ 1500 токенов, 6–8 правил,
  3–5 примеров), температура 0,2, ответ ≤ 120 слов, если не просили подробнее; результаты инструментов — роль `tool`, помечены как данные.
- [ ] Проверка ответа: время, даты, аудитории и номера в ответе есть в данных инструментов; ссылки — только из данных и
  только `*.tpu.ru`. Не сходится → ответ собирается шаблоном из данных. Неверные аргументы — одна повторная попытка,
  потом уточняющий вопрос шаблоном; > 15 с или мусор — шаблон.
- [ ] Документы: ответ — выдержка с источником, не сочинение; `found=false` → шаблон «не нашёл, вот куда обратиться».
- [ ] Поток SSE: прежние `meta`/`status`/`delta`/`done` плюс `card` (карточка инструмента) и `sources`; фронтенд на
  моках не ломается (новые события необязательны).

**Инструменты и шлюз**
- [ ] Помощник зовёт инструменты только через gateway (не rag напрямую): вход `POST /chat/tools/{name}` с сервисным
  ключом `assistant_gateway_key` (роль `chat.service`; не путать с `assistant_client_key` — входящей защитой чата),
  канал `CHAT` (`DisclosurePolicy` → `masked`); ключи консоли и MCP на этот вход не действуют, `chat.service` не
  открывает `/mcp` и консоль; свой лимит одновременных запросов для `chat.service` (по умолчанию 64 — один ключ на всех
  студентов), строка в `docs/SECURITY.md` (таблица «Кто кого вызывает»). Помощник — в сети `core` (к gateway), ml-server — по адресу из `ML_BASE_URL`.
- [ ] Инструменты части А: `docs_search`, `rasp_find` (`rasp_day`/`rasp_week` отложены до разрешения ТПУ).

**ml-server**
- [ ] Реестр провайдеров с полями `pd_allowed`, `pii` (`off`/`mask`), `trust` (`trusted_tpu`/`trusted_contract`/
  `untrusted`); помощник видит их через `/v1/models` и не шлёт личное туда, где `pd_allowed=false`.
- [ ] `pii=mask`: телефоны, почты, ФИО из словаря, номера зачёток и паспортов заменяются метками до отправки модели и
  возвращаются в ответе — в том числе на стыке кусков потока. Проверка — вручную на заглушке провайдера (тесты
  ml-server пишет другой участник команды).
- [ ] Адаптер GigaChat (обмен ключа на токен с кэшем, вызовы инструментов, поток) — если вуз выбирает GigaChat
  (вопрос 1); иначе — существующий OpenAI-совместимый.
- [ ] Ошибка потока не пишет тело ответа провайдера в журнал (сейчас путь ошибки потока в `Application.kt` пишет
  `details` — до 300 символов тела).

**Журналы, безопасность, качество**
- [ ] В журналах нет текстов чата, аргументов и результатов инструментов: `request_id`, инструмент, исход, длительность.
- [ ] Набор оценки ~100 вопросов (профиль `eval`): верный инструмент, верные аргументы, ответ сходится с данными, доля
  ответов без модели, задержка, стоимость. Порог выкладки (предложение, вопрос 3): верный инструмент ≥ 90 %, ответ
  сходится с данными ≥ 95 %, без модели ≥ 40 % вопросов.
- [ ] Стенд Сбера: «Как получить справку об обучении?» → выдержка из документа ТПУ со ссылкой; «где 10-й корпус» —
  без вызова модели; вопрос с телефоном в тексте → в журнале ml-server нет телефона, модель получила метку.

### Не входит
- Личные инструменты (профиль, расписание своей группы из ЛК, заявки, дедлайны), черновики с подтверждением —
  спецификации 4 и 6.
- Паспорт вызова, слоты из профиля, история по пользователю, лимиты по пользователю — часть Б (после identity).
- Классификатор намерений на векторах (`rag /internal/classify`) — если правил по оценке не хватит.
- Адаптеры YandexGPT, Cloud.ru; распознавание имён нейросетью (NER); биллинг.

## Часть Б — после identity (спецификация 4)
Паспорт вызова к gateway, `userId`/доверие/согласия в контексте, группа из профиля, история принадлежит пользователю
(удаление по запросу), лимиты на пользователя, отключение временного `X-Assistant-Key`. Критерии — при старте части Б.

## Ограничения
- Закон: обработка по поручению ТПУ (ст. 6 ч. 3 152-ФЗ); личное — только на ВМ ТПУ в России; личное к зарубежному
  провайдеру — трансграничная передача (ст. 12) — до решения вуза запрещено (`pd_allowed=false` у таких провайдеров).
- Ключ модели — только у ml-server; токены ТПУ помощник не видит.
- Архитектура: маршрутизатор, слоты, проверка — в assistant; маскирование и провайдеры — в ml-server; инструменты —
  в gateway. `ChatService` делится по модулям (нормализация, маршрутизатор, слоты, инструменты, проверка) — не растёт.
- Память стенда: помощник ≤ 300 МБ (сейчас 132 МБ).

## Открытые вопросы
1. Какая модель в части А: GigaChat (нужен договор/ключ; российский провайдер — `trusted_contract`, личное можно с
   маской) или текущий провайдер ml-server? От этого зависит шаг 3 и `pd_allowed`.
2. Пускать ли личное (с маской) в модель вообще до решения вуза, или в части А личного в чате нет совсем (тогда
   `pii=mask` — страховка от того, что студент сам напишет телефон)?
3. Порог качества для выкладки по набору оценки — предлагаю: верный инструмент ≥ 90 %, ответ сходится с данными ≥ 95 %,
   без модели ≥ 40 % вопросов.
4. История 30 дней без входа (анонимный `conversation_id` в браузере) — так, или до identity история не хранится?
5. ml-server: правки шагов 1–3 — в ветке `feature/native-image` (она сейчас на сервере) или в новой ветке от неё?
   Тесты ml-server по правилу команды пишет другой участник — в шагах 1–3 только код и ручная проверка.
